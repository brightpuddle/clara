# Clara Workflow & Task Authoring Guide

Clara supervises external automation scripts using a "let it fail" BEAM-style process model. Workflows and business logic live in scripts (primarily TypeScript with Bun) that interact with Clara's central Event Bus, SQLite audit store, and Model Context Protocol (MCP) tools.

---

## Directory Conventions

In `~/.config/clara/`:

```text
~/.config/clara/
├── config.yaml
├── scripts/                      # External scripts (TypeScript/Bun, Python, Shell)
│   ├── clara.ts                  # Clara TypeScript SDK helper
│   ├── clara.d.ts                # Ambient type definitions (generated by `clara types gen`)
│   └── <task_name>/              # Modular task script folder
│       └── main.ts
├── triggers-available/           # Staging / draft trigger YAMLs (dormant)
│   └── <task_name>.yaml
└── triggers/ (or tasks/)         # Active production triggers
    └── <task_name>.yaml -> ../triggers-available/<task_name>.yaml
```

## Authoring Scripts (TypeScript / Bun)

Clara provides an SDK in `scripts/clara.ts` with type-safe MCP tool calling and CloudEvent ingestion:

```typescript
#!/usr/bin/env bun
// ~/.config/clara/scripts/sync_notes/main.ts

import { readEvent, callTool, runID, triggerID } from "../clara.ts";

// 1. Ingest event data if triggered by an event
const event = await readEvent<{ query?: string }>();
console.log(`Executing under run: ${runID()}, trigger: ${triggerID()}`);

// 2. Invoke Clara MCP tools with type safety
const notes = await callTool("zk.note_search", {
  query: event.data?.query || "todo"
});

// 3. Perform work and dispatch notifications
if (notes && notes.length > 0) {
  await callTool("notify.send", {
    title: "Pending Notes Found",
    body: `Found ${notes.length} notes matching query.`
  });
}
```

### Tool Discovery & Testing

Before authoring, check available tools and type stubs:

```bash
clara tool list                     # List all MCP tools
clara tool show <tool_name>         # View parameter schema
clara tool call <tool_name> -a '{}' # Direct tool invocation
clara types gen                     # Refresh ~/.config/clara/sdk/clara.d.ts
```

## Defining Triggers

Trigger definitions configure how scripts are executed. Place drafts in `~/.config/clara/triggers-available/<id>.yaml`.

### 1. Schedule Trigger (Cron / Interval)

Runs periodically on a schedule:

```yaml
triggers:
  - id: "daily-morning-brief"
    name: "Daily Morning Briefing"
    description: "Generates daily task briefing from Obsidian vault and tasks"
    enabled: true
    type: "schedule"
    schedule: "0 8 * * 1-5" # 8:00 AM Mon-Fri (robfig/cron v3 format)
    action:
      exec: "bun"
      args: ["run", "scripts/morning_brief/main.ts"]
      dir: "${HOME}/.config/clara"
      timeout: "60s"
```

### 2. Event Trigger (Smart Boolean AST)

Evaluates incoming CloudEvents from the event bus:

```yaml
triggers:
  - id: "invoice-processor"
    name: "Invoice Processor"
    description: "Processes vendor invoice emails"
    enabled: true
    type: "event"
    debounce: 500ms           # optional: wait for quiet period before running
    throttle: 1s              # optional: rate limit executions
    match:
      and:
        - field: type
          op: equals
          value: email.received
        - or:
            - field: data.subject
              op: contains
              value: "Invoice"
            - field: data.subject
              op: regex
              value: "(?i)receipt|bill"
    action:
      exec: "bun"
      args: ["run", "scripts/process_invoice.ts"]
      dir: "${HOME}/.config/clara"
      pass_event: stdin       # stdin | env | arg | none
      timeout: "30s"
```

#### Rule Match Operators
- `equals`, `not_equals`
- `contains`, `not_contains`
- `starts_with`, `ends_with`
- `regex`
- `gt`, `gte`, `lt`, `lte`
- `exists`, `not_exists`
- Boolean groupings: `and: [...]`, `or: [...]`, `not: { ... }`

### 3. Supervised Worker Trigger (Long-Running Process)

Monitored daemon with automatic restart policies:

```yaml
triggers:
  - id: "bridge-worker"
    name: "External Sensor Worker"
    type: "worker"
    action:
      exec: "python3"
      args: ["workers/sensor_bridge.py"]
      dir: "${HOME}/.config/clara"
      restart: "on_failure"   # always | on_failure | never
      restart_delay: 5s
      max_restarts: 10
```

## Safe Staging & Deployment Workflow

To safely iterate on scripts without accidental execution or cumbersome babysitting:

1. **Author script:** Place in `~/.config/clara/scripts/<task_name>/`.
2. **Author trigger definition:** Place in `~/.config/clara/triggers-available/<task_name>.yaml`.
3. **Manual test / Dry run:**
   ```bash
   # Test script directly
   bun run ~/.config/clara/scripts/<task_name>/main.ts --dry-run
   ```
4. **Activate in Clara:**
   ```bash
   ln -s ~/.config/clara/triggers-available/<task_name>.yaml ~/.config/clara/triggers/
   ```
5. **Inspect runs & telemetry:**
   ```bash
   clara run list -n 10
   clara run show <run_id>
   ```
6. **Deactivate / Rollback:**
   ```bash
   rm ~/.config/clara/triggers/<task_name>.yaml
   ```
